## Task 4 — Merit List Engine (R + SHAP)

### R Script (packaged in Docker image)
```r
# /app/r/merit_calculation.R

library(shapr)
library(xgboost)
library(jsonlite)

calculate_merit <- function(matric_pct, fsc_pct, entry_test_score, weights) {
  # weights = list(matric=0.3, fsc=0.3, entry_test=0.4) from policy config
  
  # Normalize scores to 0-100 scale
  matric_norm <- matric_pct
  fsc_norm <- fsc_pct
  entry_test_norm <- (entry_test_score / max_entry_test_score) * 100
  
  # Weighted merit score
  merit_score <- (
    weights$matric * matric_norm +
    weights$fsc * fsc_norm +
    weights$entry_test * entry_test_norm
  )
  
  return(list(
    score = merit_score,
    matric_contribution = weights$matric * matric_norm,
    fsc_contribution = weights$fsc * fsc_norm,
    entry_test_contribution = weights$entry_test * entry_test_norm
  ))
}

explain_merit <- function(application, weights) {
  # Use SHAP to explain why student ranked where they did
  shap_values <- compute_shap_values(application, model)
  
  return(list(
    merit_score = application$merit_score,
    explanations = list(
      matric = list(value=application$matric_pct, contribution=shap_values$matric),
      fsc = list(value=application$fsc_pct, contribution=shap_values$fsc),
      entry_test = list(value=application$entry_test, contribution=shap_values$entry_test)
    )
  ))
}
```

## Task 5 — Merit List Generation

### Database Table
```sql
CREATE TABLE merit_lists (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    program_id UUID NOT NULL REFERENCES programs(id),
    semester_id UUID NOT NULL REFERENCES semesters(id),
    quota_type VARCHAR(50) NOT NULL,
    round_number INT NOT NULL, -- 1st, 2nd, 3rd
    total_seats INT NOT NULL,
    generated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    generated_by UUID NOT NULL REFERENCES users(id),
    status VARCHAR(20) NOT NULL DEFAULT 'draft', -- draft | published | closed
    published_at TIMESTAMPTZ,
    UNIQUE(program_id, semester_id, quota_type, round_number)
);

CREATE TABLE merit_list_entries (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    merit_list_id UUID NOT NULL REFERENCES merit_lists(id),
    application_id UUID NOT NULL REFERENCES applications(id),
    merit_rank INT NOT NULL,
    merit_score DECIMAL(10, 2) NOT NULL,
    seat_allocated BOOLEAN DEFAULT FALSE,
    allocation_status VARCHAR(20), -- allocated | waitlist | rejected
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### Merit List Generation Workflow
1. AdmissionsHead enters: Program, Semester, Quota Type
2. System calls `IMeritCalculationService.GenerateMeritListAsync()`
3. R script calculates merit for all applications in that quota
4. System creates `merit_lists` (status=draft) and `merit_list_entries` (ranked by score)
5. AdmissionsHead reviews draft → can tweak up to ±5% per policy config
   - If tweaking >5%: requires VC + Chancellor approval (cross-dept permission request)
6. AdmissionsHead publishes → status=published → send auto-notification to applicants

### Tweak Logic
- AdmissionsHead can change individual student's merit rank (which changes others' ranks)
- Every change logged in audit log with reason
- If change exceeds ±5% threshold: flag and route to VC for approval

```sql
);
```

### Allocation Logic
- Allocate seats from top of merit list
- Total seats per program per quota: defined in program setup
- If more qualified candidates than seats: create waitlist
- Waitlist moves to allocated if someone declines

### Waitlist Management
- Applicant ranked 51st in merit but only 50 seats: goes to waitlist
- Can receive bump if top-50 candidate declines
- Automatic notification when bumped
