# Nocturne — Sprint 1: Foundation (Cloud Agnostic + Policy Engine + RBAC + Audit + Academic Calendar)

## Role
You are a senior .NET 10 / C# 14 architect building the foundational layer of Nocturne — a multi-tenant university ERP platform. Everything built in this sprint is load-bearing. Every other sprint depends on it. Get it right.

## Task 1 — Cloud Agnostic Storage Abstraction

### Interface
```csharp
public interface IStorageProvider
{
    Task<string> UploadAsync(string path, Stream content, string contentType, CancellationToken ct = default);
    Task<Stream> DownloadAsync(string path, CancellationToken ct = default);
    Task DeleteAsync(string path, CancellationToken ct = default);
    Task<bool> ExistsAsync(string path, CancellationToken ct = default);
    Task<IReadOnlyList<string>> ListAsync(string prefix, CancellationToken ct = default);
}
```

### Implementations — one class per provider, all registered via DI based on `NOCTURNE_STORAGE_PROVIDER` env var:
- `LocalDiskStorageProvider` — writes to configurable base path
- `S3StorageProvider` — S3-compatible (works with MinIO, AWS S3, Wasabi, Backblaze B2)
- `AzureBlobStorageProvider` — Azure Blob Storage
- `SftpStorageProvider` — SFTP via SSH.NET

Registration in `Program.cs`:
```csharp
builder.Services.AddStorageProvider(builder.Configuration);
```

Rule: No code outside the storage provider implementations may reference any cloud SDK directly. All file operations go through `IStorageProvider`.

## Task 3 — RBAC + Federated Permission System

### Role Hierarchy (top to bottom)
```
SuperAdmin (Nocturne Systems only)
  └── ViceChancellor
        ├── Registrar
        ├── Chancellor (peer, not subordinate)
        ├── Dean
        │     └── HOD (Head of Department)
        │           └── Faculty
        ├── AdmissionsHead
        ├── FinanceHead
        ├── HRHead
        ├── LibraryHead
        ├── TransportHead
        ├── HostelHead
        └── ExamController
              └── Student
                    └── Parent/Guardian
```

### Database Tables

```sql
CREATE TABLE roles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(100) NOT NULL UNIQUE,
    display_name VARCHAR(200) NOT NULL,
    parent_role_id UUID REFERENCES roles(id),
    department_scope VARCHAR(100), -- null = university-wide
    is_system_role BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE permissions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    module VARCHAR(100) NOT NULL,
    action VARCHAR(50) NOT NULL, -- view | create | edit | delete | approve | export
    resource VARCHAR(100) NOT NULL,
    description TEXT,
    UNIQUE(module, action, resource)
);

CREATE TABLE role_permissions (
    role_id UUID NOT NULL REFERENCES roles(id),
    permission_id UUID NOT NULL REFERENCES permissions(id),
    granted BOOLEAN NOT NULL DEFAULT TRUE,
    PRIMARY KEY (role_id, permission_id)
);

CREATE TABLE user_roles (
    user_id UUID NOT NULL REFERENCES users(id),
    role_id UUID NOT NULL REFERENCES roles(id),
    department_id UUID REFERENCES departments(id), -- scoped to dept if set
    assigned_by UUID NOT NULL REFERENCES users(id),
    assigned_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at TIMESTAMPTZ,
    PRIMARY KEY (user_id, role_id)
);
```

### Federated Permission Rule
- A department head (e.g., AdmissionsHead) has FULL permissions on their own module
- Any action that affects ANOTHER department's data requires a cross-department permission request
- Cross-department requests are logged and routed to the relevant department head for approval
- VC can grant cross-department permissions unilaterally

### Cross-Department Permission Request Table
```sql
CREATE TABLE cross_dept_permission_requests (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    requesting_user_id UUID NOT NULL REFERENCES users(id),
    requesting_dept_id UUID NOT NULL REFERENCES departments(id),
    target_dept_id UUID NOT NULL REFERENCES departments(id),
    permission_id UUID NOT NULL REFERENCES permissions(id),
    reason TEXT NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'pending', -- pending | approved | rejected
    reviewed_by UUID REFERENCES users(id),
    reviewed_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### Implementation
- Implement as ASP.NET Core Policy-based authorization
- `[RequirePermission("admissions", "edit", "merit_list")]` attribute
- Middleware checks permission on every request
- Cache permission lookups in Redis with 5-minute TTL, invalidate on role change

## Task 4 — Immutable Audit Log

### Database Table
```sql
CREATE TABLE audit_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    actor_id UUID REFERENCES users(id),
    actor_email VARCHAR(200),
    action VARCHAR(100) NOT NULL,
    module VARCHAR(100) NOT NULL,
    entity_type VARCHAR(100) NOT NULL,
    entity_id VARCHAR(200),
    old_value JSONB,
    new_value JSONB,
    ip_address INET,
    user_agent TEXT,
    session_id VARCHAR(200),
    occurred_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Immutability: no UPDATE or DELETE permitted on this table
-- Enforce via PostgreSQL row security policy:
CREATE POLICY audit_log_no_delete ON audit_logs FOR DELETE USING (FALSE);
CREATE POLICY audit_log_no_update ON audit_logs FOR UPDATE USING (FALSE);
ALTER TABLE audit_logs ENABLE ROW LEVEL SECURITY;
```

### Service
```csharp
public interface IAuditService
{
    Task LogAsync(AuditEntry entry, CancellationToken ct = default);
    Task<PagedResult<AuditEntry>> QueryAsync(AuditQuery query, CancellationToken ct = default);
}
```

### Automatic Logging
- Intercept all EF Core SaveChanges via an interceptor
- Automatically capture Added/Modified/Deleted entity states
- Never log: passwords, tokens, encryption keys, raw connection strings

## Task 5 — Academic Calendar Engine

### Database Tables
```sql
CREATE TABLE academic_years (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(50) NOT NULL, -- e.g. "2024-25"
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    is_current BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE semesters (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    academic_year_id UUID NOT NULL REFERENCES academic_years(id),
    name VARCHAR(50) NOT NULL, -- Fall 2024, Spring 2025
    type VARCHAR(20) NOT NULL, -- fall | spring | summer
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    exam_start_date DATE,
    exam_end_date DATE,
    result_declaration_date DATE,
    add_drop_end_date DATE,
    is_current BOOLEAN NOT NULL DEFAULT FALSE,
    status VARCHAR(20) NOT NULL DEFAULT 'upcoming', -- upcoming | active | exams | completed
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE academic_holidays (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    semester_id UUID REFERENCES semesters(id),
    academic_year_id UUID NOT NULL REFERENCES academic_years(id),
    name VARCHAR(200) NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    type VARCHAR(50) NOT NULL -- public_holiday | university_holiday | exam_break
);
```

### Service
```csharp
public interface IAcademicCalendarService
{
    Task<Semester> GetCurrentSemesterAsync(CancellationToken ct = default);
    Task<bool> IsAddDropOpenAsync(CancellationToken ct = default);
    Task<bool> IsExamPeriodAsync(CancellationToken ct = default);
    Task<int> GetWorkingDaysAsync(DateOnly from, DateOnly to, CancellationToken ct = default);
    Task<IReadOnlyList<AcademicHoliday>> GetUpcomingHolidaysAsync(int days = 30, CancellationToken ct = default);
}
```

Rule: Every other module that needs date context (attendance denominators, fee deadlines, exam eligibility) calls `IAcademicCalendarService` — never hardcodes dates.
