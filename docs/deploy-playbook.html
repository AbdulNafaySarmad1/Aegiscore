Pre-Flight — Before You Touch the Server

5 min
💡
Do this at home the night before This phase has zero risk. You are just collecting information.
  1. Get the server IP and SSH credentials from the client

    You need three things from their IT person:

    Server IP203.0.113.50The public IP of the Ubuntu 24 server
    SSH userubuntu or rootWho you log in as
    SSH key or password~/.ssh/client_key.pemHow you authenticate
    ⚠
    If they don't have a server yet Any Ubuntu 24 VPS works. DigitalOcean, Hetzner, Linode, AWS EC2 — pick the $20/month tier minimum. You need 8GB RAM.
  2. Get the subdomain they want

    Ask: "What URL should people use to access the ERP?"

    Typical answer: erp.clientuniversity.edu.pk or aegiscore.clientuniversity.edu.pk

  3. Confirm: Do they have a managed database or are we running everything on this server?

    If they say "We have a managed database" → You need their connection string. Ask for it now.

    If they say "Everything on this server" → Good. LOCAL mode. No extra steps.

  4. SSH into the server to verify you can reach it
    ssh ubuntu@203.0.113.50

    If you see a welcome prompt, you're in. Type exit to leave for now.

    ⚠
    Connection refused? The server firewall might be blocking port 22. Ask their IT to open it, or use their cloud console's browser-based SSH.
P1

Phase 1 — Install Docker on the Server

5 min
💡
Run this once, never again Docker is a one-time install. After this, deployments are just docker compose commands.
  1. SSH into the server
    ssh ubuntu@203.0.113.50
  2. Update packages
    sudo apt update && sudo apt upgrade -y
  3. Install Docker (official script, one command)
    curl -fsSL https://get.docker.com | sudo sh

    This downloads and installs Docker Engine and Docker Compose together. Takes about 2 minutes.

  4. Add yourself to the docker group (so you don't need sudo every time)
    sudo usermod -aG docker $USER
  5. Log out and back in for the group change to take effect
    exit
ssh ubuntu@203.0.113.50
  6. Verify Docker is working
    docker --version
docker compose version
    ✅
    Expected output You should see version numbers like "Docker version 28.x.x" and "Docker Compose version v2.x.x". If you see both, Docker is ready.
    ⚠
    "docker: command not found" You might need to start a fresh shell. Try newgrp docker or just SSH in again. If that doesn't work, run sudo systemctl enable docker --now.
P2

Phase 2 — Clone AegisCore and Generate Secrets

5 min
  1. Clone the repository onto the server
    git clone https://github.com/nocturnesystems/aegiscore.git /opt/aegiscore
cd /opt/aegiscore
    💡
    Customize this URL Replace the GitHub URL with wherever your AegisCore repo actually lives. If the client is air-gapped, scp a tarball instead and extract it to /opt/aegiscore.
  2. Make the scripts executable
    chmod +x scripts/*.sh
  3. Run the bootstrap script
    ./scripts/bootstrap-env.sh

    The script will ask:

    Question 1"Which deployment mode? (1) LOCAL (2) CLOUD (3) HYBRID"
    Question 2(If CLOUD) "Which secrets provider?"
    💡
    Which mode to pick Pick LOCAL if everything runs on this one server. Pick CLOUD if the client has a managed PostgreSQL service (RDS, Azure DB, Cloud SQL). The script handles everything else automatically.

    The script generates a .env file with all cryptographic secrets, database passwords, and configuration. It prints a masked summary — you'll see every key name but the values are hidden.

    ✅
    You should see "Created .env with mode 600" followed by a list of masked keys like AEGISCORE_JWT_SECRET=****, POSTGRES_PASSWORD=****, etc.
  4. If you picked CLOUD mode: edit .env and paste the database connection strings

    Open .env in nano:

    nano .env

    Find these two lines and fill them in:

    DATABASE_URL=Host=mydb.postgres.database.azure.com;Port=5432;Database=aegiscore;Username=aegiscore@mydb;Password=THEIR_PASSWORD;SslMode=Require
REDIS_URL=myredis.redis.cache.windows.net:6380,password=THEIR_PASSWORD,ssl=True

    Press Ctrl+X, then Y, then Enter to save and exit nano.

    ⚠
    Connection string format The connection string MUST be in Npgsql format for PostgreSQL and StackExchange.Redis format for Redis. If you're unsure, ask the client's DBA to provide them in these exact formats.
P3

Phase 3 — Deploy (this is the big one)

10–15 min
💡
One command This is the only deploy command you need. The script handles building, starting, migrating, and verifying.
  1. Run the deploy script
    ./scripts/deploy.sh local

    Use ./scripts/deploy.sh cloud or ./scripts/deploy.sh hybrid to match your mode from Phase 2.

  2. What happens, in order, and what you'll see

    The script runs through these stages. Watch the terminal output:

    1. Validate .envChecks DEPLOYMENT_MODE matches. If it doesn't, stops immediately with a clear error.
    2. Build imagesDocker builds the API and Portal containers. You'll see dotnet restore and npm install scroll by. First time: 3-5 minutes. Subsequent: 30 seconds (cached).
    3. Start containersYou'll see Container aegiscore-postgres-1 Healthy and similar lines. Wait for all services to report Healthy.
    4. Wait for PostgresScript pauses, checking every 2 seconds. You'll see dots printing: ....... Usually 10-15 seconds.
    5. Run migrationsEF Core creates all 200+ database tables. You'll see Applying migration V2_0_ExtendedPlatformModules and similar lines. Takes 5-15 seconds.
    6. Health checkScript curls the health endpoint every 5 seconds: Attempt 1/30... Attempt 2/30.... Stops as soon as it gets HTTP 200.
    7. BannerBig ASCII art banner with URLs and mode.
  3. What the success banner looks like
    ====================================================
 AegisCore — Deployment Complete
 Mode:       LOCAL
 Portal:     http://localhost:3000
 API:        http://localhost:8080
 Health:     OK (200)  —  responded in 2.1s
 Timestamp:  2026-08-05 14:32:15 UTC
====================================================
⚠
What if health check fails after 30 attempts? The script exits with an error. Run docker compose logs api to see what the API container is complaining about. 90% of the time it's a database connection issue — check the DATABASE_URL format in .env. 9% of the time it's a port conflict — something else is using port 3000 or 8080. 1% of the time it's a genuine bug — read the logs and look for "FATAL" or "Exception".

P5

Phase 5 — Set Up the Domain & SSL

10 min
💡
This makes it a real website Right now the app is on an IP address with a port number. This phase gives it a proper domain name with HTTPS.
  1. Ask the client to create a DNS record

    Tell them: "Log into your domain registrar and add this record:"

    TypeNameValueTTL
    Aerp203.0.113.503600 (or Auto)

    This creates erp.clientuniversity.edu.pk pointing to your server.

    ⚠
    DNS takes time It can take anywhere from 2 minutes to 4 hours for DNS to propagate globally. Test with: ping erp.clientuniversity.edu.pk. If it resolves to your server IP, DNS is ready.
  2. Install Nginx
    sudo apt install nginx -y
  3. Create the Nginx config
    sudo nano /etc/nginx/sites-available/aegiscore

    Paste this entire block (replace the domain):

    server {
    listen 80;
    server_name erp.clientuniversity.edu.pk;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/ {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    client_max_body_size 50m;
}
  4. Enable the site and test the config
    sudo ln -s /etc/nginx/sites-available/aegiscore /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
    ✅
    Expected output nginx: configuration file /etc/nginx/nginx.conf test is successful

    Now http://erp.clientuniversity.edu.pk should load the AegisCore login page.

  5. Install Certbot and get SSL (automatic, free)
    sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d erp.clientuniversity.edu.pk

    Certbot will ask:

    Email addressEnter yours — used for expiry warnings
    Terms of serviceType A to agree
    Redirect HTTP to HTTPS?Type 2 (Redirect)

    That's it. Certbot automatically:

    • Obtains a free Let's Encrypt certificate (valid 90 days)
    • Configures Nginx to serve HTTPS
    • Sets up a cron job to auto-renew the certificate before expiry
  6. Verify HTTPS works

    Open https://erp.clientuniversity.edu.pk. You should see the green padlock in your browser's address bar.

    ✅
    Done The ERP is now accessible at a proper domain with HTTPS. You are production-ready.
P6

Phase 6 — Production Hardening

3 min
💡
Do these before you hand over the server Three quick things that prevent problems later.
  1. Restrict .env permissions
    chmod 600 /opt/aegiscore/.env

    Only the file owner can read it. All secrets are now locked down.

  2. Set up auto-restart on reboot
    sudo tee /etc/systemd/system/aegiscore.service <<'EOF'
[Unit]
Description=AegisCore ERP
After=docker.service
Requires=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/opt/aegiscore
ExecStart=/usr/bin/docker compose up -d
ExecStop=/usr/bin/docker compose down
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable aegiscore

    Now if the server reboots (power outage, kernel update), AegisCore starts automatically. No human needed.

  3. Set up firewall
    sudo ufw allow 22/tcp    # SSH
sudo ufw allow 80/tcp    # HTTP
sudo ufw allow 443/tcp   # HTTPS
sudo ufw enable
sudo ufw status
    ✅
    Expected You should see ports 22, 80, and 443 ALLOW. Ports 3000 and 8080 should NOT be in the list — they're only accessible from inside the server now.

Quick Reference — If Something Goes Wrong

Reference
ProblemFix
"docker: command not found" Docker didn't install or you're not in the docker group. Run: sudo usermod -aG docker $USER then newgrp docker. If still broken: sudo apt install docker.io docker-compose-v2 -y
"port is already allocated" Something is using port 3000 or 8080. Find it: sudo lsof -i :3000 and sudo lsof -i :8080. Kill the process or change the ports in .env.
"connection refused" during health check API didn't start. Run docker compose logs api | tail -50. Look for "FATAL" or "Exception" lines. 90% chance the database connection string in .env is wrong.
"migration failed" Database schema mismatch. Run docker compose exec api dotnet ef database update manually and read the error. If a migration is corrupted, you may need to drop and recreate the database (emergency only).
SSL certificate doesn't work DNS hasn't propagated yet. Wait 30 minutes. Test with dig erp.clientuniversity.edu.pk — if it doesn't return your server IP, DNS is not ready. Certbot needs DNS to resolve before it can issue a certificate.
"502 Bad Gateway" from Nginx Portal or API container is down. Run docker compose ps — all services should show "Up" and "healthy". If a service shows "unhealthy" or "exited", restart it: docker compose restart api or docker compose restart portal.
Server ran out of disk space Docker images and logs accumulate. Run docker system prune -a --volumes to clean everything unused. Warning: this deletes stopped containers and unused images. Don't run while AegisCore is running.
Need to update AegisCore 
cd /opt/aegiscore
git pull
./scripts/deploy.sh local
This rebuilds, restarts, and runs any new migrations automatically. About 2-3 minutes of downtime on LOCAL mode.
